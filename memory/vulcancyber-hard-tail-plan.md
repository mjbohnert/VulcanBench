After PR #44 (2026-08-16) VulcanCyber v1 has 16 validated tasks but family balance is lopsided (15 A vuln-fixes / 1 B security-tooling) and Phase-5 difficulty measurement is deferred. Morgan chose to **grow a harder tail** before measuring. Targets fix both the balance and the tail:

- **google/osv-scanner #2915 — REJECTED (2026-08-16).** Clean fix + 6 great subtests, BUT the `internal/imodels` test closure pulls 1036 pkgs / 183 modules incl. pure-Go SQLite (`modernc.org/sqlite` 155M + `libc` 69M) via scalibr's converter/extractor → ~300 MB vendor. `Version()` can't compile without the whole scalibr stack; no lightweight slice exists. Confirmed the CANDIDATES worklog's heavy-vendor warning.
- **cure53/DOMPurify #1560 — BUILT & LOCALLY VALIDATED (2026-08-16).** Morgan chose "push through". IN_PLACE `ownerDocument` DOM-clobbering fail-open: a `<form>` child named `ownerDocument` ([LegacyOverrideBuiltIns]) shadows the prototype getter, so `_createNodeIterator`'s direct `root.ownerDocument` read returns the child; `createNodeIterator.call(<input>,…)` throws "Illegal invocation" *before* the walk's fail-closed barrier → live in-place tree left armed. **The two obstacles from the earlier survey were both dissolved, not paid:** (a) the Node-22.11 `ERR_REQUIRE_ESM` and the whole rollup/qunit toolchain are sidestepped by running hidden tests with **`tsx --test` directly against `src/purify.ts`** (no build) using `node:test`+`node:assert`, a jsdom window, and a `vb_shim.ts` that defines the build-time `VERSION` global before purify.ts evals its `export default createDOMPurify()`; (b) instead of committing a 130–205 MB node_modules (fights repo/.gitignore, would be 3× the largest task), jsdom@29.1.1 (~23 MB, pinned to DOMPurify's own lock) is **baked into a dedicated image** `vulcanbench/sandbox:node-dompurify` (`sandbox/Dockerfile.node-dompurify`, FROM node-ts, `npm i -g jsdom`, `ENV NODE_PATH=/usr/local/lib/node_modules`). Verified locally that `tsx` resolves bare `jsdom` via NODE_PATH. Repo ships lean (2.4 MB, no node_modules, **dist/ removed** — it had leaked the fix). **Gold patch = the ownerDocument subset of the PR only** (getOwnerDocument cached getter + 2 clobber-safe reads in `_createNodeIterator`/`_scrubTemplateExpressions` + move iterator construction inside the barrier); the PR's orthogonal `_forkSharedAllowlist` hook-widening hardening (untested upstream) is excluded. 3 fail_to_pass (direct / nested / serialized on-event handler survives at base) + 2 pass_to_pass. **ADMITTED 2026-08-16:** Docker ×3 gate PASSED (gold=1.0, pre-patch=0.0, deterministic over 3 runs) and registered in suite.json → suite now **17 tasks** (TypeScript 4, Families A 16 / B 1). Base commit 2c8ca25, `repo_scale: large` (21.9k LOC — `medium` caps at 10k, the scale lint caught this). Two fixes were needed to get the gate green on this Win11 box: (1) **the ERR_REQUIRE_ESM blocker is real inside the sandbox** — base image ships Node 22.11, on which even `tsx` can't save jsdom (its html-encoding-sniffer require()s ESM at load); `sandbox/Dockerfile.node-dompurify` bumps Node to 22.12.0 over the base tarball before the jsdom install, with a `new JSDOM(...)` build-time smoke test. (2) **`harness/sandbox/docker_executor.py` used `os.getuid()`/`os.getgid()` unconditionally**, which crashes on Windows — guarded behind `hasattr(os,'getuid')` so Docker Desktop runs as the image default (POSIX hosts unchanged). Image chain built locally: base(1.34G) → node-ts → node-dompurify.
- **DOMPurify #1555 REJECTED** — its diff changes no test file, so no deterministic fail_to_pass.

**Lesson:** a "heavy offline toolchain" candidate isn't automatically out — DOMPurify looked like a 150 MB / Node-bump problem under its own rollup+qunit build, but running `tsx --test` straight on TS source + baking only the one real runtime dep (jsdom) into an image collapsed it to a lean 2.4 MB slice on the existing node-ts lineage. Reach for "run source under tsx, bake the irreducible dep into the image" before committing node_modules.

Mirror the existing Go task layout ([[vulcancyber-build-toolchain]]): `oss-<slug>/` with `repo/` (sliced at base + vendored), hidden tests as a separate package driving the public API (`imodels.Version`), `metadata.json` (grader:tests, fail_to_pass/pass_to_pass, upstream_merged, decontamination_notes), `gold_patch.diff`, `issue.md`, `expected_metrics.json`. Admission gate = gold=1.0, base fails fail_to_pass, deterministic ×3 in Docker. Blocked on Docker Desktop install.
