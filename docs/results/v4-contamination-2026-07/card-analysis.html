We thought we’d caught the model cheating.
We’d caught our own harness.

13 eval tasks Opus 5 could have memorised vs. 13 it couldn’t — run four times as we fixed what we were really measuring.
1 · the smoking gun wasn’t
One “failed” task spent 21s working and 1785s frozen on a single network request. Six of 13 losses were stalls, not wrong answers.
2 · the fix was wrong too
Our first timeout cap killed a reply that legitimately took 333s. Big repos are slow: 30s typical on small ones, 333s on large.
3 · the leftover gap
Both halves hold the same languages — but the older half packs 11 big repos to the newer half’s 8. Big repos run out of clock.
Strip out the stalls and the clock, and the model got exactly one task wrong on each side.
The suite was contaminated — and it never showed up in the score.
26 real merged pull requests · Python, Rust, TypeScript, JavaScript, Go · hidden tests, offline sandbox
It solves ~90% either way, so this rules out a big advantage, not a small one.
